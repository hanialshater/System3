# Tone style guide

**evidence: sourced** (the need for an explicit guide), **evidence: hypothesis** (the specific rules proposed below)

## Why an explicit guide

Fashion copywriting best practice calls for an explicit tone-of-voice document — approved words, banned superlatives, tone variants for different contexts — applied consistently so the voice stays recognizable regardless of who or what wrote a given line. Trunk Club maintained a public internal voice-and-tone guide for exactly this reason.

Source: https://sites.google.com/a/trunkclub.com/copywriting-style-guide/voice-and-tone

When multiple agents (or an LLM across many generations) produce commentary, they should draw from one shared micro-style-guide rather than each inventing tone independently — otherwise the customer experiences the same "personality shift" problem named in [cold-start-copy.md](cold-start-copy.md), just from inconsistent authorship instead of an evidence-tier jump.

## Starter rules (test these — see the loop)

- Sentence length: short. One claim per sentence (see [explain-vs-persuade.md](explain-vs-persuade.md)).
- Banned: superlatives with no evidence behind them ("perfect," "everyone loves," "guaranteed").
- Preferred hedge vocabulary: use the exact phrasing table in [hedging-fit-claims.md](hedging-fit-claims.md) rather than improvising synonyms — consistency here is part of what makes the hedge legible as a hedge.
- Preferred voice: first person, help-seeker (see [voice-help-seeker.md](voice-help-seeker.md)).
- Tone shifts by category tier: informational/restrained for [../categories/premium-designer.md](../categories/premium-designer.md) and [../personas/luxury-aspirational.md](../personas/luxury-aspirational.md); can be warmer/more enthusiastic for [../personas/trend-seeker.md](../personas/trend-seeker.md) and mainstream categories — but "warmer" still means no unsupported claims, see [../commentary/README.md](../commentary/README.md).

This file is explicitly a starting point, not a finished guide — run it through [../process/try-search-eval-improve-loop.md](../process/try-search-eval-improve-loop.md) and tighten or loosen these rules based on what actually reads well.
